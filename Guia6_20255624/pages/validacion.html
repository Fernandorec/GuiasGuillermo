Investigación: expresiones regulares en JavaScript

Una expresión regular (regex o RegExp) es un patrón que describe un conjunto de cadenas de texto. Sirve para validar formatos (carnet, DUI, correo), buscar coincidencias dentro de un texto y reemplazar partes de él. En JavaScript son objetos de tipo RegExp y se pueden crear de dos formas:
  • Literal: const re = /^[A-Z]{2}\d{3}$/; (la más común)
  • Constructor: const re = new RegExp("^[A-Z]{2}\\d{3}$"); (útil cuando el patrón se arma dinámicamente; hay que duplicar las barras invertidas)

Símbolo Significado Ejemplo
^ y $Inicio y fin de la cadena (anclas). Sin ellas, la regex acepta coincidencias parciales./^\d+$/ solo dígitos
.Cualquier carácter (excepto salto de línea)/a.c/ → "abc"
\d / \DDígito / no dígito\d{3} → "123"
\w / \WLetra ASCII, número o _ / lo contrario\w+ → "user_1"
\s / \SEspacio en blanco / no espacio\s+

( ) y (?: )Grupo con captura / grupo sin captura(\d{2})-(\d{2})

\Escapa un carácter especial\. es un punto literal

Banderas (flags): i ignora mayúsculas/minúsculas, g busca todas las coincidencias, m multilínea, u habilita Unicode (permite \p{L} para cualquier letra, con tildes y ñ).

  • regex.test(texto) → devuelve true o false. Es el método ideal para validar formularios (el que usamos aquí).
  • regex.exec(texto) → devuelve el detalle de la coincidencia (con sus grupos) o null.
  • texto.match(regex) → devuelve las coincidencias (todas si lleva la bandera g) o null.
  • texto.matchAll(regex) → iterador con todas las coincidencias y sus grupos (requiere g).
  • texto.replace(regex, nuevo) → reemplaza coincidencias; replaceAll con g reemplaza todas.
  • texto.search(regex) → posición de la primera coincidencia (o -1).
  • texto.split(regex) → divide el texto usando el patrón como separador.
const re = /^[A-Za-z]{2}\d{3}$/;
re.test("AB001");   // true
re.test("A1001");   // false
"25/12/2001".match(/(\d{2})\/(\d{2})\/(\d{4})/); // ["25/12/2001", "25", "12", "2001"]

  • Usar siempre ^ y $ al validar, para que la cadena completa cumpla el formato (si no, "xxAB001xx" pasaría).
  • Una regex valida el formato, no el sentido: "31/02/2001" cumple el formato de fecha pero no existe. Por eso este ejemplo añade una comprobación con Date.
  • No usar la bandera g con test() en validaciones repetidas: la regex recuerda su posición (lastIndex) y puede dar resultados alternados.
  • La validación en el navegador mejora la experiencia, pero no sustituye la validación en el servidor.
  • Para correos, una regex razonable evita casos obvios; la validación definitiva es enviar un correo de confirmación.
  • Herramientas para practicar: regex101.com, regexr.com y la documentación de MDN ("Regular expressions").
